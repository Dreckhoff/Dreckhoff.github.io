Magical Unemployment

A roguelike deckbuilder about being unemployed: send job applications by day, fight absurd card duels by night.

Mornings are for cover letters, booster drafts, and furnishing your tiny apartment. Evenings you battle a ladder of bosses — from Stinkender Sebastian ("I skipped the shower just for this duel") to the final Personalabteilung. Rejection letters pile up in your inbox; if one miraculously turns into an interview, the job itself is decided in a special duel against Die Personalerin. Two ways to win a run: land the job, or beat all eight bosses and stop needing one.

What's in the game?

A full run loop: economy, deckbuilding, base building, and turn-based combat.

Day cycle & job hunt

Applications cost postage and dignity, replies arrive days later as (mostly) creative rejections — each one a readable email thread with your absurd cover letter. Interview invitations lead to a winnable job duel.

Deckbuilding & drafting

45+ cards defined purely in YAML: dragons, bureaucracy monsters, graveyard reanimators, risky lands like the Jobcenter (extra mana, costs life). Boosters are draft picks — three cards shown, keep one — with themed packs per archetype.

Combat with real decisions

Choose attackers, hold creatures back as blockers, activate abilities (sacrifice the Aktenschredder to reanimate your best creature). Bosses have pixel-art faces, taunts, and rule-bending abilities — one makes your hand unreadable.

Base building

Furnish your rented flat along a small tech tree: a mini-fridge grants extra life, the canned-beer pallet on top of it trades hand size for health, and the dragon poster on the wall buffs every dragon you play.

Download & play

All you need is Python 3.11+ and five minutes.

1. Get the game

Clone the repository (or download it as a ZIP from GitHub and unpack it):

git clone https://github.com/Dreckhoff/magical_unemployment.git
cd magical_unemployment

2. Start it

macOS: double-click Magical Unemployment.command in the project folder — on first launch it sets up its own Python environment and installs the dependencies automatically. That's it.

Any platform, from a terminal:

python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python play_gui.py

There is an in-game tutorial in the main menu. Dependencies are just pygame-ce, pyyaml, and pytest.

Add your own content — seriously, it's easy

This game is built to be contributed to. Everything is plain text.

Cards are 15 lines of YAML

A new card is a single YAML file: name, cost, stats, tags, and effects picked from a documented library (damage, draw, auras, triggers, reanimation, activated abilities). No engine code, no build step — drop the file in data/cards/ and it's in the game.

Pixel art is literally text

Every sprite — card icons, boss faces, apartment furniture — is a character grid where each letter is a palette color. You can draw a card icon in a text editor, or in a chat message. A converter snippet turns small PNGs into grids automatically.

Bosses, furniture, whole archetypes

New opponents are a dozen lines of data (life, abilities, a pixel face, and — most importantly — their taunts). Apartment furniture needs a catalog entry, a sprite, and a spot in the room. The guide covers all of it step by step.

The contribution guide

The full guide lives as CONTRIBUTING.md in the repository root, with a printable PDF version in docs/. No Git skills required — a YAML file or a text grid pasted into a message is a perfectly valid contribution.

Under the hood

The interesting part, if you ask me: the architecture borrows habits from scientific computing.

Cards are data, not code

Every card is a ~15-line YAML file with stats, tags, and a list of effects. The engine has no idea specific cards exist — it only interprets effect descriptions. Adding a card never touches engine code, the same way a good simulation separates model parameters from the integrator.

Composable effect engine

Effects (deal_damage, reanimate, mill, auras, triggers, activated abilities) are small registered handler functions. Continuous effects are never cached: a creature's current stats are recomputed on demand from the full game state — state is derived, not duplicated, so it cannot go stale.

Event bus for emergence

Game events (creature_entered, card_drawn, creature_died) are published on a bus; cards subscribe while in play. That's how a card written today can interact with one written next year without either knowing the other exists — interactions emerge from local rules.

Headless core, 220+ tests

The rules engine imports no graphics library at all — it runs headless, which makes it fully unit-testable. Every card ships with its own pytest; the GUI is a thin rendering layer on top and is smoke-tested against a dummy video driver in CI fashion. Even the sound effects are synthesized sine waves — the repository contains no binary assets, only text.
